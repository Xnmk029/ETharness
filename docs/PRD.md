# 产品定位文档：ETharness —— 记忆优先的创作伴侣

> 版本：v0.1 ｜ 日期：2026-08-01 ｜ 状态：草案（基于市场客群分析）
> 前置：`DESIGN-PI.md`（记忆内核设计）、`research/`（生态调研）

## 1. 产品定位

**一句话**：一个以 pi 为底层、面向生活与创作的图形化 harness——**记忆是第一体验，聊天是入口**。

**定位声明**：
- 给谁：创作者（小说/剧本/内容/知识管理）与 AI 重度生活用户
- 解决什么：AI 会话记忆丢失导致的创作上下文崩塌（人物设定、世界观、伏笔、素材、偏好）
- 凭什么赢：Everything 式记忆寻址（过滤/标签/时间线/确定性地址引用）做成 GUI 第一体验——市场上没有任何 GUI 客户端把"记忆寻址"当核心
- 形态：本地优先（隐私卖点）、免费开源（OSS 影响力路线）、Electron/Tauri GUI 壳 + pi 内核

**不做什么**（反定位）：
- 不做"又一个聊天壳"（Cherry Studio/Chatbox 红海）
- 不做"编程工具换皮"（客群错位）
- 不做云优先（隐私是生活向用户的核心诉求）

## 3. 核心差异化：记忆寻址的 GUI 化

Everything 语法是底层引擎，界面是它的可视化：

| 语法能力 | GUI 呈现 |
|---|---|
| `type:character` | 标签栏点击过滤（人物/世界观/灵感/素材/决策…） |
| `entity:苏晚` | 实体卡片（点击人物头像查看全部关联记忆） |
| `since:2w` | 时间线滑动（拖回两周前） |
| `#A1F3` | **地址引用**：AI 回答中可点击的引用（"关于伏笔，见 #A1F3"），一键跳转展开原文 |
| `imp:>0.7` | 重要性排序开关（星标筛选） |
| `--` 排除 | 高级过滤栏（可展开的完整语法输入，供进阶用户） |
| 自动记忆地图 | 会话开启时侧栏显示"今日相关记忆"（首轮评估注入的 GUI 化） |

**关键设计原则：语法藏起来，体验露出来。** 普通用户全程不需要知道语法存在；进阶用户可展开完整语法输入框（开发者友好，延续 pi 基因）。

## 6. 模型特化支持：DeepSeek 缓存感知记忆层（新特性）

### 6.1 机制事实（官方文档，2026-08 确认）

| 项 | 事实 |
|---|---|
| 缓存方式 | 磁盘缓存，默认开启，前缀匹配，无需改代码 |
| 命中单价 | **$0.0028/M**（V4-Flash）vs 未命中 $0.14/M——**50 倍差价** |
| 匹配规则 | SWA 下缓存是"独立完整单元"，请求须**完整匹配缓存前缀单元**才命中；三种持久化：请求边界、**公共前缀检测**、固定 token 间隔 |
| 持久性 | 不活跃后几小时至几天自动清除（"较为长效"） |
| 性质 | best-effort，缓存构建需几秒；只匹配输入前缀 |
| 计量 | usage 字段：`prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` |
| 即将实施 | 高峰期（9-12点/14-18点北京时间）2x 定价——**缓存命中的价值更高** |

### 6.2 核心洞察

**DeepSeek 免费缓存 = Agent MFT 记忆注入的存储底座。** 记忆地图作为稳定前缀注入时，成本从 $0.14/M 降到 $0.0028/M；对话轮次天然命中（历史即前缀）；**跨会话复用**需要稳定的公共前缀——这正是"全局缓存机制"（项目最初构思）的技术闭环。

### 6.3 四大特性设计

**特性 1：稳定热区注入（Stable Hot Zone）**

记忆注入分两层：

```
稳定层（前缀友好，进 system prompt）   ← 高 importance 记忆，固定槽位排序
  - importance 分桶，桶内按 addr 稳定序（绝不按 score 重排）
  - 跨会话、跨请求内容完全不变 → 触发"公共前缀检测"持久化为独立缓存单元
  - 默认 16K~32K token 窗口
动态层（近用户消息）                ← 按当前 prompt 检索的记忆，变化不影响稳定层命中
```

**与传统做法的根本区别：排序稳定性 > 排序最优性。** 每次按 score 重排会破坏缓存单元，导致稳定层整体 miss。

**特性 2：缓存统计面板（Cache Telemetry）**

- 从 API 响应 usage 读取 `prompt_cache_hit/miss_tokens`（pi 的 message usage 可捕获）
- 面板显示：本次命中率、记忆注入节省成本、累计节省
- 叙事：**"记忆不花钱"——用真实数字证明**

**特性 3：缓存窗口管理（Cache Window Manager）**

- 热区大小可配置（默认 16K-32K token）
- 记忆进稳定层的准入策略：importance × 访问频率 × **内容稳定性**（易变记忆禁止进稳定层）
- 冷区记忆走 `mem_get` 惰性展开（单次小请求，不破坏前缀）

**特性 4：跨会话全局缓存（Global Cache）**

- 稳定前缀（system + 项目上下文 + 稳定记忆层）跨会话复用
- 新会话开启：前缀命中 → 记忆注入近零成本 + 首 token 延迟降低（磁盘缓存加速前缀计算）
- **这是项目最初"全局缓存机制"构思的最终闭环**

### 6.4 实现要点（pi 集成）

- 稳定层：`before_agent_start` 修改 system prompt（前缀最前端，天然稳定位）
- 动态层：message 注入（现有 agent-mft 机制，保持）
- 缓存数据采集：`message_end` 读取 usage（扩展可改写 usage 展示）
- 模式开关：`cacheMode: "deepseek" | "off"`——特化优化不影响其他 provider

### 6.5 风险

| 风险 | 对策 |
|---|---|
| best-effort，不保证命中 | 稳定层设计最大化命中概率；统计面板实测验证 |
| pi 的 tool 定义/settings 变化破坏前缀 | 稳定层只依赖 system prompt 尾部追加，降低耦合；实测观察 |
| 只对 DeepSeek 生效 | 可配置模式；DeepSeek 用户本就是中文创作者主力，客群契合 |
| 峰值 2x 定价 | 缓存命中在高峰期价值翻倍——稳定层更值钱 |

## 7. 记忆模型扩展

现有 KINDS（编程向）→ 扩展创作/生活向：

```
现有：decision / fact / preference / task_state / entity_rel / commit / note
新增：character（人物设定）/ world（世界观）/ idea（灵感）/ material（素材）/
      plan（计划）/ event（剧情事件）/ style（风格偏好）
```

示例场景：
- `mem_add {filename: "苏晚：左眼失明，怕黑但嘴硬", kind: character, entity: 苏晚}`
- `mem_add {filename: "第三章埋下怀表伏笔", kind: event, entity: 怀表, path: 小说A/第三章}`
- 会话开启自动注入："今日相关记忆" = `entity:苏晚 OR type:world` 的寻址结果 GUI 化

```
┌───────────────────────────────────────────────┐
│ 🔍 [人物] [世界观] [灵感] [素材] [全部]  ←标签栏  │
│ 实体：苏晚 ▾   时间：全部 ▾   重要性：★>0.7      │
├───────┬─────────────────────────┬──────┬───────┤
│ 地址   │ 记忆                    │ 类型 │ 时间   │

│ #B7C2 │ 第三章伏笔：怀表          │ 事件 │ 昨天   │
│ ...   │                         │      │       │
└───────┴─────────────────────────┴──────┴───────┘
 点击行 → 展开原文 + 来源回溯 | 右键 → 编辑/取代/撤销
```

### 7.2 对话界面（记忆优先版）
- 左侧：记忆地图侧栏（首轮评估注入的 GUI 化，可折叠）

- 输入框下：快捷记忆按钮（"记住这条"、"存为人物设定"）

### 7.3 创作工作区（阶段 2）
- 人物卡列表（entity: character 的记忆聚合视图）
- 世界观/伏笔看板（按 path 分组）

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| "记忆优先"不是真实买点 | P0/P1 阶段做创作者访谈（最痛的 3 个记忆场景），用反馈校准 |

| 与 pi 生态距离（用户不懂 pi） | GUI 是独立产品体验；pi 是内核不是招牌 |
