# 产品定位文档：ETharness —— 记忆优先的创作伴侣

> 版本：v0.1 ｜ 日期：2026-08-01 ｜ 状态：草案（基于市场客群分析）
> 前置：`DESIGN-PI.md`（记忆内核设计）、`research/`（生态调研）

---

## 1. 产品定位

**一句话**：一个以 pi 为底层、面向生活与创作的图形化 harness——**记忆是第一体验，聊天是入口**。

**定位声明**：
- 给谁：创作者（小说/剧本/内容/知识管理）与 AI 重度生活用户
- 解决什么：AI 会话记忆丢失导致的创作上下文崩塌（人物设定、世界观、伏笔、素材、偏好）
- 凭什么赢：Everything 式记忆寻址（过滤/标签/时间线/确定性地址引用）做成 GUI 第一体验——市场上没有任何 GUI 客户端把"记忆寻址"当核心
- 形态：本地优先（隐私卖点）、免费开源（OSS 影响力路线）、Electron/Tauri GUI 壳 + pi 内核

**不做什么**（反定位）：
- 不做"又一个聊天壳"（Cherry Studio/Chatbox 红海）
- 不做"编程工具换皮"（客群错位）
- 不做云优先（隐私是生活向用户的核心诉求）

## 2. 目标客群

### 2.1 一级客群：创作者（首发聚焦）

| 细分 | 记忆痛点场景 | 付费习惯 | 优先级 |
|---|---|---|---|
| 小说/剧本作者 | 人物设定、世界观、伏笔、时间线跨会话丢失；"AI 忘了主角的伤疤" | 好（Scrivener/Notion 付费习惯） | ★★★ |
| 内容创作者（公众号/视频/博客） | 素材库、选题、风格偏好、历史观点的跨会话一致性 | 好（剪映/知识星球生态） | ★★☆ |
| 知识工作者（研究者/咨询） | 访谈记录、结论链、来源溯源 | 中 | ★★☆ |

### 2.2 二级客群：AI 生活用户

| 细分 | 记忆痛点 | 优先级 |
|---|---|---|
| AI 日记/陪伴用户 | "AI 记得我的家人、计划、习惯" | ★☆☆（规模大但后置） |
| 家庭事务管理 | 采购清单、孩子安排、健康记录 | ★☆☆ |

### 2.3 客群规模参照

- Cherry Studio 模式证明：中文 GUI 免费客户端可做到亿级下载、活跃中文社区
- 创作用户付费习惯远好于纯开发者工具用户
- pi 生态（万级）是种子用户来源，不是天花板

## 3. 核心差异化：记忆寻址的 GUI 化

Everything 语法是底层引擎，界面是它的可视化：

| 语法能力 | GUI 呈现 |
|---|---|
| `type:character` | 标签栏点击过滤（人物/世界观/灵感/素材/决策…） |
| `entity:苏晚` | 实体卡片（点击人物头像查看全部关联记忆） |
| `since:2w` | 时间线滑动（拖回两周前） |
| `#A1F3` | **地址引用**：AI 回答中可点击的引用（"关于伏笔，见 #A1F3"），一键跳转展开原文 |
| `imp:>0.7` | 重要性排序开关（星标筛选） |
| `--` 排除 | 高级过滤栏（可展开的完整语法输入，供进阶用户） |
| 自动记忆地图 | 会话开启时侧栏显示"今日相关记忆"（首轮评估注入的 GUI 化） |

**关键设计原则：语法藏起来，体验露出来。** 普通用户全程不需要知道语法存在；进阶用户可展开完整语法输入框（开发者友好，延续 pi 基因）。

## 4. 竞品对照

| 维度 | Cherry Studio | Chatbox | LobeChat | AnythingLLM | **ETharness** |
|---|---|---|---|---|---|
| 聊天为中心 | ✅ | ✅ | ✅ | ✅ | 记忆为中心 |
| 记忆寻址语言 | ❌ | ❌ | ❌ | ❌（RAG 黑盒） | ✅ 唯一 |
| 确定性地址引用 | ❌ | ❌ | ❌ | ❌ | ✅ 唯一 |
| 创作工作区 | ❌ | ❌ | ❌ | 文档库 | ✅ 人物卡/世界观 |
| 本地优先 | ⚠️ | ⚠️ | ❌ | ✅ | ✅ |
| 可重建投影 | ❌ | ❌ | ❌ | ❌ | ✅ |
| 底层可编程性 | ❌ | ❌ | ⚠️ | ⚠️ | ✅（pi 内核 + CLI） |

**空位确认**：GUI 客户端全部是"聊天 + RAG 知识库"范式；"可寻址、可引用、可追溯"的记忆是第一体验的客户端——不存在。

## 5. 产品形态与架构

```
┌────────────────────────────────────────────────┐
│ ETharness GUI（Electron/Tauri）                  │
│  ├─ 对话界面    （创作向：长文编辑/灵感捕获/草稿箱）│
│  ├─ 记忆浏览器  （标签/时间线/过滤栏/地址引用跳转）  │
│  ├─ 创作工作区  （人物卡/世界观/素材/伏笔管理）     │
│  └─ 设置        （模型接入，复用 pi provider 体系）│
├────────────────────────────────────────────────┤
│ pi 内核（RPC 桥接）                               │
│  ├─ LLM 网关（多 provider，pi 现成）              │
│  ├─ 会话管理（pi 现成）                           │
│  └─ agent-mft 记忆内核（已实现，扩展 kind）        │
└────────────────────────────────────────────────┘
```

**技术复用清单**：
- `@earendil-works/pi-web-ui`（官方 Web UI 组件，v0.75.3）——对话界面基础
- pi RPC 协议——GUI 壳 ↔ 内核通信
- agent-mft 全量（query/addr/mirror/rebuild/runtime/tools）——记忆内核零重写
- pi 扩展生态——创作工具（写作辅助、素材抓取）可后续接入

## 6. 记忆模型扩展

现有 KINDS（编程向）→ 扩展创作/生活向：

```
现有：decision / fact / preference / task_state / entity_rel / commit / note
新增：character（人物设定）/ world（世界观）/ idea（灵感）/ material（素材）/
      plan（计划）/ event（剧情事件）/ style（风格偏好）
```

示例场景：
- `mem_add {filename: "苏晚：左眼失明，怕黑但嘴硬", kind: character, entity: 苏晚}`
- `mem_add {filename: "第三章埋下怀表伏笔", kind: event, entity: 怀表, path: 小说A/第三章}`
- 会话开启自动注入："今日相关记忆" = `entity:苏晚 OR type:world` 的寻址结果 GUI 化

## 7. 界面设计（MVP 三个界面）

### 7.1 记忆浏览器（首发核心界面）
```
┌───────────────────────────────────────────────┐
│ 🔍 [人物] [世界观] [灵感] [素材] [全部]  ←标签栏  │
│ 实体：苏晚 ▾   时间：全部 ▾   重要性：★>0.7      │
├───────┬─────────────────────────┬──────┬───────┤
│ 地址   │ 记忆                    │ 类型 │ 时间   │
│ #A1F3 │ 苏晚：左眼失明，怕黑嘴硬 │ 人物 │ 3天前  │
│ #B7C2 │ 第三章伏笔：怀表          │ 事件 │ 昨天   │
│ ...   │                         │      │       │
└───────┴─────────────────────────┴──────┴───────┘
 点击行 → 展开原文 + 来源回溯 | 右键 → 编辑/取代/撤销
```

### 7.2 对话界面（记忆优先版）
- 左侧：记忆地图侧栏（首轮评估注入的 GUI 化，可折叠）
- AI 回答中的 `#地址` 可点击 → 展开原文浮层
- 输入框下：快捷记忆按钮（"记住这条"、"存为人物设定"）

### 7.3 创作工作区（阶段 2）
- 人物卡列表（entity: character 的记忆聚合视图）
- 世界观/伏笔看板（按 path 分组）
- 素材库（拖拽导入 → 自动生成记忆条目）

## 8. 里程碑

| 阶段 | 内容 | 验证指标 |
|---|---|---|
| **P0 技术验证**（2-3 周） | pi RPC + pi-web-ui 最小 GUI 壳：对话 + 记忆浏览器只读 | 本地跑通；记忆寻址 GUI 化可行 |
| **P1 MVP 开源**（6-8 周） | 完整记忆浏览器 + 对话 + 快捷记忆 + 记忆地图侧栏 | GitHub stars、下载量、社区反馈 |
| **P2 创作工作区**（后续） | 人物卡/世界观/素材 + 写作辅助模板 | 创作者实际产出作品（自带传播） |
| **P3 扩展** | macOS 版、插件生态、进阶用户语法模式 | 社区插件数 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| "记忆优先"不是真实买点 | P0/P1 阶段做创作者访谈（最痛的 3 个记忆场景），用反馈校准 |
| GUI 开发量大 | 复用 pi-web-ui + RPC；MVP 严格限定两个界面 |
| Cherry Studio 等加记忆功能 | 无寻址语言基因；先发 + 开源社区绑定 + 记忆内核深度 |
| 生活向隐私敏感 | 本地优先（数据不出机器）作为核心卖点 |
| 与 pi 生态距离（用户不懂 pi） | GUI 是独立产品体验；pi 是内核不是招牌 |

## 10. 开源策略（goal: OSS）
