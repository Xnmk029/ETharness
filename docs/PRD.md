# 产品定位文档：ETharness —— 记忆优先的创作伴侣

> 版本：v0.1 ｜ 日期：2026-08-01 ｜ 状态：草案（基于市场客群分析）
> 前置：`DESIGN-PI.md`（记忆内核设计）、`research/`（生态调研）

## 1. 产品定位

**一句话**：一个以 pi 为底层、面向生活与创作的图形化 harness——**记忆是第一体验，聊天是入口**。

**定位声明**：
- 给谁：创作者（小说/剧本/内容/知识管理）与 AI 重度生活用户
- 解决什么：AI 会话记忆丢失导致的创作上下文崩塌（人物设定、世界观、伏笔、素材、偏好）
- 凭什么赢：Everything 式记忆寻址（过滤/标签/时间线/确定性地址引用）做成 GUI 第一体验——市场上没有任何 GUI 客户端把"记忆寻址"当核心
- 形态：本地优先（隐私卖点）、免费开源（OSS 影响力路线）、Electron/Tauri GUI 壳 + pi 内核

**不做什么**（反定位）：
- 不做"又一个聊天壳"（Cherry Studio/Chatbox 红海）
- 不做"编程工具换皮"（客群错位）
- 不做云优先（隐私是生活向用户的核心诉求）

## 2. 目标客群

### 2.1 一级客群：创作者（首发聚焦）

| 细分 | 记忆痛点场景 | 付费习惯 | 优先级 |
|---|---|---|---|
| 小说/剧本作者 | 人物设定、世界观、伏笔、时间线跨会话丢失；"AI 忘了主角的伤疤" | 好（Scrivener/Notion 付费习惯） | ★★★ |
| 内容创作者（公众号/视频/博客） | 素材库、选题、风格偏好、历史观点的跨会话一致性 | 好（剪映/知识星球生态） | ★★☆ |
| 知识工作者（研究者/咨询） | 访谈记录、结论链、来源溯源 | 中 | ★★☆ |

### 2.2 二级客群：AI 生活用户

| 细分 | 记忆痛点 | 优先级 |
|---|---|---|
| AI 日记/陪伴用户 | "AI 记得我的家人、计划、习惯" | ★☆☆（规模大但后置） |

### 2.3 客群规模参照

- pi 生态（万级）是种子用户来源，不是天花板

## 3. 核心差异化：记忆寻址的 GUI 化

Everything 语法是底层引擎，界面是它的可视化：

| 语法能力 | GUI 呈现 |
|---|---|
| `type:character` | 标签栏点击过滤（人物/世界观/灵感/素材/决策…） |
| `entity:苏晚` | 实体卡片（点击人物头像查看全部关联记忆） |
| `since:2w` | 时间线滑动（拖回两周前） |
| `#A1F3` | **地址引用**：AI 回答中可点击的引用（"关于伏笔，见 #A1F3"），一键跳转展开原文 |
| `imp:>0.7` | 重要性排序开关（星标筛选） |
| `--` 排除 | 高级过滤栏（可展开的完整语法输入，供进阶用户） |
| 自动记忆地图 | 会话开启时侧栏显示"今日相关记忆"（首轮评估注入的 GUI 化） |

**关键设计原则：语法藏起来，体验露出来。** 普通用户全程不需要知道语法存在；进阶用户可展开完整语法输入框（开发者友好，延续 pi 基因）。

## 6. 常驻记忆体系：与 DeepSeek 缓存的有机结合

### 6.0 设计立场

**产品概念（钉住的记忆永远在场）独立成立，DeepSeek 免费缓存是放大器，不是依赖。**

缓存机制的本质是"前缀即资产"：前缀 = 一次性构建成本 + 之后近乎免费的常驻；前缀越稳定越被复用，资产价值越高。因此记忆注入从"每次组装的成本项"升级为"常驻工作记忆"——这本来就是记忆优先产品应有的概念，缓存只是让常驻免费。

### 6.1 机制事实（官方文档，2026-08 确认，可信赖）

| 项 | 事实 |
|---|---|
| 缓存方式 | 磁盘缓存，默认开启，前缀匹配，无需改代码 |
| 命中单价 | **$0.0028/M**（V4-Flash）vs 未命中 $0.14/M——**50 倍差价** |
| 匹配规则 | SWA 下缓存是"独立完整单元"，请求须**完整匹配缓存前缀单元**才命中；三种持久化：请求边界、**公共前缀检测**、固定 token 间隔 |
| 持久性 | 不活跃后几小时至几天自动清除（"较为长效"） |
| 性质 | best-effort，缓存构建需几秒；只匹配输入前缀 |
| 计量 | usage 字段：`prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` |
| 即将实施 | 高峰期（9-12点/14-18点北京时间）2x 定价——**缓存命中的价值更高** |

### 6.2 四层记忆体系（有机结合后的核心架构）

```
常驻记忆区（Resident Memory）— 稳定前缀，跨会话免费在场
  · 创作人格/风格（系统提示，固定不动）
  · 钉住的记忆（用户/AI 钉住：人物卡、世界观、伏笔、关键设定）
  · 高分记忆（importance ≥ 阈值，按 addr 稳定序——绝不重排）
  → DeepSeek 公共前缀检测持久化 → 跨会话命中
会话卷宗（Work Volume）— 自然前缀
  · 一个作品 = 一个持久卷宗（历史对话即前缀，续写天然免费）
  · pi fork/clone 共享前缀 → 分叉探索成本归零
动态记忆区（Dynamic）— 近用户消息
  · 按当前 prompt 检索的记忆（evaluateInjection）
  · 变化不影响常驻区命中
冷记忆（Cold）— 按需
  · mem_get 惰性展开（单次小请求，不碰前缀）
```

**设计原则：一切可稳定的都稳定，一切可变的都后置。**（前缀友好是产品原则，不只是缓存技巧）

### 6.3 GUI 有机结合点（用户可感知）

| 概念 | 技术机制 | 用户看到的 |
|---|---|---|
| 钉住 = 在场 | 钉住的记忆进常驻区（稳定前缀） | 记忆浏览器"常驻区"，点击人物卡钉住 → 从此每次对话都在场 |
| 在场指示 | 常驻区命中状态 | 对话顶部："本作品 12 条记忆在场，续写命中 99%" |
| 卷宗续写 | 长会话前缀免费 | "继续写第三章" → 前缀命中，秒回且近零成本 |
| 资产仪表盘 | usage 缓存字段汇总 | "常驻记忆 24K token，本月节省 $X"——记忆资产可视化 |
| 热度联动 | 常驻命中频率回写 importance | 记忆条目显示"热/常驻/冷"，热记忆自动建议钉住 |

### 6.4 产品叙事

> **"钉住的记忆永远在场，而且不花你的钱。"**
> Pinned memories are always present — for free.

整合四层战略：记忆优先（差异化）＋ DeepSeek 免费缓存（成本结构）＋ 全局缓存机制（最初构思）＋ 创作连续性（客群痛点）。

### 6.5 边界与风险

| 风险 | 对策 |
|---|---|
| 钉住无限制 → 前缀膨胀 | 常驻区配额（默认 16K-32K token），GUI 容量条，超限提示替换 |
| supersede/revoke 触发前缀重建 | 低频可接受；批量操作合并为一次重建 |
| 仅 DeepSeek 免费 | 常驻区是所有 provider 的产品概念；DeepSeek 免费，其他模式提示计入正常 token |
| 易变记忆进常驻区 → 频繁重建 | 准入策略：importance × 访问频率 × 内容稳定性，易变记忆禁入 |

### 6.6 对 agent-mft 内核的改动

- mirror 增加 `pinned`（0/1）+ `pinned_at` 字段
- 记忆地图两段式：常驻段（pinned ∪ importance≥阈值，按 addr 序）＋ 动态段
- 常驻段注入 system prompt 尾部（`before_agent_start` 改 systemPrompt）；动态段保持 message 注入
- 新增 `mem_pin` / `mem_unpin` 工具 + `/mft:pin` 命令
- 缓存遥测：`message_end` 读 usage → 仪表盘数据表（命中率/节省累计）

## 7. 记忆模型扩展

现有 KINDS（编程向）→ 扩展创作/生活向：

```
现有：decision / fact / preference / task_state / entity_rel / commit / note
新增：character（人物设定）/ world（世界观）/ idea（灵感）/ material（素材）/
      plan（计划）/ event（剧情事件）/ style（风格偏好）
```

示例场景：
- `mem_add {filename: "苏晚：左眼失明，怕黑但嘴硬", kind: character, entity: 苏晚}`
- `mem_add {filename: "第三章埋下怀表伏笔", kind: event, entity: 怀表, path: 小说A/第三章}`
- 会话开启自动注入："今日相关记忆" = `entity:苏晚 OR type:world` 的寻址结果 GUI 化

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| "记忆优先"不是真实买点 | P0/P1 阶段做创作者访谈（最痛的 3 个记忆场景），用反馈校准 |
| GUI 开发量大 | 复用 pi-web-ui + RPC；MVP 严格限定两个界面 |
| Cherry Studio 等加记忆功能 | 无寻址语言基因；先发 + 开源社区绑定 + 记忆内核深度 |
| 生活向隐私敏感 | 本地优先（数据不出机器）作为核心卖点 |
| 与 pi 生态距离（用户不懂 pi） | GUI 是独立产品体验；pi 是内核不是招牌 |
